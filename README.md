**Pre-Work Assignment: AI-Based Content Creation and Distribution Workflow**
**Innoventure AI Content Studio**
An AI-assisted prototype created for the Innoventure pre-work assignment. The application takes one campaign idea and a selected target audience, then prepares four platform-specific content drafts for review.

**GitHub repository:** https://github.com/Shushrusha-dev/innoventure-ai-content-studio
Project objective
Demonstrate how one campaign idea can be adapted into multiple content formats for Innoventure's audiences: school leaders, teachers, parents, and students (Grades 1–9).
Features implemented
- Campaign idea input and target audience selection.
- Audience-aware content generation using the Google Gemini API.
- Generation of all four supported content formats for the selected audience:
  - LinkedIn post
  - Instagram caption and five-slide carousel
  - YouTube Shorts title and 30–45 second script
  - Newsletter subject, preview text, body, and call to action
- Audience-specific tone and messaging.
- Predefined local backup templates when the Gemini API key is unavailable or an API request fails.
- Editable drafts for human review.
- Approval and saving of approved drafts to data/content.csv.
- Audience-based recommended distribution channels, with a multi-select control to create a distribution plan.
- Saving distribution plans to data/distribution.csv with a scheduled/manual publishing status.
- Performance dashboard with reach, views, engagement, and clicks, including illustrative sample data.
Audience-based distribution recommendations
The app recommends channels according to the selected audience. These recommendations are used in the distribution-planning step; they do not change the four content formats generated by the AI.
Audience	Recommended channels in the current prototype
School Leaders	LinkedIn, School Email, Newsletter
Teachers	LinkedIn, Instagram, Teacher Groups, Newsletter
Students (Grades 1–9)	YouTube Shorts, School LMS, Teacher Sharing, Classroom Display
Parents	Instagram, Facebook, Parent WhatsApp Groups, Newsletter


The selectable channel options are configured in the channels dictionary in app.py. Add or edit entries there to change the recommendations.

The application creates the data/ directory when it runs. Depending on the actions performed, it stores:
- content.csv – approved generated content.
- distribution.csv – selected channels and distribution status.
- analytics.csv – sample or supplied performance data.
The expected analytics CSV columns are Platform, Audience, Reach, Views, Engagement, and Clicks. Use numeric values for the metric columns.
Run locally (Windows)
1. Clone the repository
git clone https://github.com/Shushrusha-dev/innoventure-ai-content-studio.git
cd innoventure-ai-content-studio
2. Create and activate a virtual environment
python -m venv venv
venv\Scripts\activate
3. Install dependencies
python -m pip install --upgrade pip
pip install -r requirements.txt
4. Configure the Gemini API key
Copy the example environment file:
copy .env.example .env
Open .env and add your own key:
GEMINI_API_KEY=your_gemini_api_key_here
Do not upload .env or share your API key. The repository's .gitignore excludes .env.
5. Start the Streamlit application
streamlit run app.py
Streamlit will provide a local URL (normally http://localhost:8501) to open in your browser.
How to use the prototype
1. Enter a campaign idea.
2. Select one target audience.
3. Generate the four content drafts.
4. Review and edit the drafts in the application.
5. Approve and save the content.
6. Select recommended distribution channels and record the distribution plan.
7. Open the performance dashboard. Use Load Illustrative Sample Data to view example metrics, or provide actual metric records in data/analytics.csv using the columns shown in the app.
Current scope and limitations
- Publishing: The prototype records a distribution plan with a Scheduled / Manual Publishing status. It does not directly publish posts to LinkedIn, Instagram, YouTube, email, WhatsApp, or school platforms. Actual publishing would require the relevant platform APIs, permissions, and integrations.
- Analytics: The current dashboard displays reach, views, engagement, and clicks. It uses illustrative sample data or locally supplied analytics records; automatic weekly collection from platform APIs is not implemented.
- Subscribers and leads: These are not currently calculated by the prototype. They can be added when reliable source data and integrations are available.
- Gemini availability: If the API key is missing or a request fails, the application falls back to predefined audience-specific templates. Backup output is template-based, not Gemini-generated.
- Distribution options: The current multi-select control uses the audience's configured recommendations. Update the channels dictionary in app.py to add or change available options.
Security
Keep the Gemini API key in your local .env file. Never commit .env, API keys, or other credentials to GitHub. Use .env.example only as a placeholder template.
